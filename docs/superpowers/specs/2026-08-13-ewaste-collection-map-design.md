# 우리동네 폐가전 수거함 (ewaste-info) 설계

## 배경

`local-data-pipeline`을 공유 데이터 소스로 삼아 `dongne-info`(재활용 배출정보,
초록/노랑), `parking-lot`(주차장 정보, 네이비+옐로우)에 이은 세 번째 지역
검색형 생활정보 사이트. 이번 소스는 한국환경공단이 배포한
`한국환경공단_폐전자제품 수거함 위치정보_20241028.csv`(폐휴대폰·중소폐가전
수거함 위치, 12,830건). 색상/폰트는 기존 두 사이트와 완전히 다르게, 시니어
사용자의 가독성을 최우선으로 설계한다.

## 원본 데이터

- 컬럼: `순번, 상호명, 수거종류, 수거방법, 수거장소(주소), 장소구분, 수거비용`
- 인코딩: CP949(EUC-KR)
- `수거종류`: 폐휴대폰(7,503) / 중소폐가전(5,327) — 값 2종뿐
- `수거방법`, `수거비용`: 전부 "수거함 설치" / "무상" 단일값 — UI에 노출할 가치 낮음(생략)
- `장소구분`: 민팃ATM(7,242, 56%) / 공동주택·아파트(3,662) / 지자체(774) /
  롯데하이마트(372) / KT대리점(261) / LG베스트샵(231) / 삼성디지털프라자(162) /
  제주 재활용도움센터(126)
- 위도/경도 컬럼 없음 → 지도 UI 불가, dongne-info와 같은 **텍스트 검색형**으로 설계
- 주소 품질 문제: 시도명이 "경기"/"경기도" 등 약칭·정식명 혼용, 일부는
  공백 없이 시군구와 붙어있음("경북김천시"), 시도명 없이 시군구부터 시작하는
  행 7건(김포시/안양시/용인시/남양주시/창원시/김천시, 전체의 0.05%)

## 아키텍처

### 1. 데이터 파이프라인 (`local-data-pipeline`, 기존 저장소에 추가)

- `sources/e_waste.py`: CSV 파서. CP949 인코딩 명시해서 읽음. `bag_stores_xls.py`처럼
  헤더 그대로 dict로 반환하는 단순 파서.
- `utils/regions.py`에 시도 약칭 정규화 함수 추가 (`normalize_sido_abbr` 등):
  - 17개 시도의 약칭 → 정식명 매핑 테이블 (예: "경기"→"경기도", "경북"→"경상북도",
    "서울"/"서울시"→"서울특별시" 등 2~3글자 축약형 전부)
  - 매핑 적용 후 기존 `parse_sido_sigungu` 재사용
  - 시도명 없이 시군구로 시작하는 예외 7건은 소규모 하드코딩 테이블
    (김포시/안양시/용인시/남양주시→경기도, 창원시→경상남도, 김천시→경상북도)로 보완
- `load_e_waste.py`: 실행 스크립트. `raw_data/한국환경공단_폐전자제품 수거함 위치정보_20241028.csv`
  읽어서 지역별로 그룹핑, `merge_region_file(..., "e_waste", ...)`로
  `data/by_region/*.json`에 병합 저장. 매칭 실패 건수는 로그로 출력(스킵).

### 2. 사이트 (`ewaste-info`, 신규 저장소)

`dongne-info`와 동일 스택: Next.js 16(App Router) + Tailwind 4, 전체 지역
정적 생성(SSG). 지도 없음.

```
ewaste-info/
  src/app/page.tsx                  # 홈 (지역 검색)
  src/app/[sido]/[sigungu]/page.tsx # 지역 상세 (SSG)
  src/app/sitemap.ts / robots.txt
  src/components/RegionSearch.tsx   # 홈 검색 (dongne-info 패턴 참고, 새 스타일)
  src/components/CollectionPointList.tsx # 수거함 목록: 수거종류 뱃지 필터 + 장소구분별 아코디언
  src/lib/regions.ts                # data/by_region JSON 파싱
  src/lib/site.ts                   # SITE_URL, SITE_NAME
  data/by_region/                   # local-data-pipeline에서 sync-data로 복사
```

- 홈: 지역명 검색 → 지역 상세 이동 (지도 없이 텍스트 검색만, dongne-info와 동일 UX)
- 지역 상세: 수거함 목록을 **수거종류(폐휴대폰/중소폐가전) 뱃지 필터** +
  **장소구분별 아코디언 그룹핑**(민팃ATM/공동주택/지자체/하이마트 등)으로 표시.
  아이콘 + 텍스트 라벨을 함께 써서 색상만으로 구분하지 않음(색약 고려).
- 공동주택(아파트) 항목: 동/호수 정보가 없어 단지명까지만 정확하다는 안내
  문구를 목록 상단에 고정 표시 ("공동주택 수거함은 외부인 이용이 제한될 수
  있습니다").
- 데이터 없는 지역: "등록된 수거함이 없습니다" 안내 카드.
- `npm run sync-data`로 `../local-data-pipeline/data/by_region` 복사 (기존
  두 사이트와 동일한 명령/패턴).

## 디자인 시스템 — 시니어 가독성 최우선

### 폰트

- **코디 UD 온고딕(KoddiUD OnGothic)** — 저시력자·고령자 가독성을 목표로
  설계된 유니버설 디자인 폰트, 무료/상업적 사용 가능. Noto Sans 등 범용
  고딕체 대신 사용.
- 본문 최소 18px, 줄간격 1.7~1.8배, 자간 살짝 넓힘
- 헤더/큰 숫자는 볼드 굵기 적극 사용 (컬러보다 굵기로 위계 구분)

### 색상 (A안: 버건디 + 크림)

| 용도 | 색상 | 비고 |
|---|---|---|
| 배경 | 크림 `#FBF6EE` | 순백 대신 눈부심 적은 톤 |
| 헤더/포인트 텍스트 | 딥 버건디 `#6B1E2E` | 로고, 헤더, 강조 |
| 본문 텍스트 | 다크 차콜브라운 `#2B2320` | 버건디는 큰 글자에만, 본문은 근검정으로 가독성 확보 |
| CTA/버튼 | 톤다운 코퍼 `#9C5B33` | 버건디와 구분되는 별도 강조색, 버튼·링크 전용 |
| 보더/구분선 | 웜 라이트탄 `#E4D7C3` | |

- 본문 대비 4.5:1(WCAG AA) 이상, 헤더류 7:1(AAA) 목표 — 구현 시 실제 대비비
  체크 도구로 검증
- 정보 구분에 색상만 쓰지 않음: 뱃지는 색+아이콘+텍스트 라벨 조합
- 버튼/터치 영역 최소 48px, 포커스 상태(focus-visible) 명확히 표시

## 배포

- 도메인: `https://ewaste-info.zucca100.com` (Gabia DNS CNAME 등록,
  `parking-for-all`과 동일 절차)
- Vercel 프로젝트명 `ewaste-info` 시도, `*.vercel.app` 별칭 선점 시
  `parking-lot` 사례처럼 별도 별칭으로 대체
- SSO 배포 보호 기본 해제 필요 여부 확인 (`vercel project protection disable`)

## 에러 처리 / 데이터 검증

- `load_e_waste.py`에서 지역 매칭 실패 건수를 로그로 출력 (전량 스킵하지 않고
  원인 파악 가능하게)
- `npm run build`로 전체 지역 페이지 SSG 성공 확인 (dongne-info/parking-lot과
  동일하게 페이지당 Vercel ISR 용량 제한 고려 — 이번 데이터는 지역당 최대
  수백 건 수준이라 parking-lot의 거주자우선주차 같은 대량 중복 이슈는 없을
  것으로 예상되나 build 시 재확인)

## 테스트 계획

- `load_e_waste.py` 실행 후 매칭 실패 건수가 예상 범위(수십 건 이하)인지 확인
- `npm run build`로 전체 지역 정적 생성 성공 확인
- 로컬 `npm run dev`로 데이터 없는 지역/공동주택 안내 문구/뱃지 필터 동작 육안 확인
